# السكة

تطبيق ويب تقدمي عربي RTL لمشاركة الطريق والمواصلات الجماعية فقط.

## هوية التطبيق

السكة ليست تطبيق طلب سيارة من نقطة إلى نقطة، ولا تتضمن نظام أوبر أو التاكسي الفردي.

الأنظمة المعتمدة:

1. **جاي في سكتك:** الكابتن ينشر مساره والمقاعد المتاحة، والراكب يطلب مقعدًا على الجزء المناسب من الطريق.
2. **مشوارنا واحد:** يجمع النظام طلبات الركاب المتقاربة في نقطة البداية والنهاية والميعاد (حتى 2 كم و30 دقيقة) في مجموعة واحدة أمام الكابتن. يختار الكابتن مركبة تستوعب إجمالي المقاعد، ويمكنه قبول عروض الركاب أو إدخال إجمالي تكلفة للمجموعة؛ تقسم قاعدة البيانات الإجمالي على عدد المقاعد وتعرض السعر الموحد لكل راكب. كل راكب يؤكد العرض من حسابه.
3. **خطوط السكة:** خطوط ثابتة بمحطات مرتبة وأيام تشغيل وميعاد أسبوعي، مع مراجعة إدارية وحجز مقاعد حسب الرحلة.

فئات المركبات المسموح بها فقط:

- ملاكي
- سوزوكي
- ميكروباص

## التقنيات

- Vite
- Supabase Auth وPostgres وRLS
- Cloudflare Pages
- OpenStreetMap / OSRM لمسارات الطريق

## إعداد المتغيرات

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY` (Publishable key)

لا تضع `service_role` أو أي Secret Key في الواجهة أو GitHub.

## Cloudflare Pages

- Build command: `npm run build`
- Build output directory: `dist`

## خطوط السكة

تُنشأ الخطوط بواسطة كابتن لديه مركبة معتمدة واشتراك مستوفٍ لشروط التشغيل، وتظل مخفية عن الركاب حتى اعتماد الإدارة. يتم إنشاء سجل رحلة عند أول حجز على موعد محدد، مع قفل صف الرحلة أثناء الحجز لمنع تجاوز عدد المقاعد. إلغاء الحجز قبل موعد التحرك يعيد المقاعد المتاحة.

## ملاحظات تشغيلية وحدود النسخة الحالية

- اختيار مواقع ومحطات الخطوط يتم حاليًا بإدخال اسم المحطة وإحداثياتها؛ اختيارها مباشرة من خريطة تفاعلية ما زال ضمن أعمال الاستكمال.
- تجميع «مشوارنا واحد» يعتمد حاليًا على تقارب إحداثيات البداية والنهاية والميعاد، ويعاد التحقق من ذلك داخل قاعدة البيانات قبل قبول المجموعة. تقسيم إجمالي تكلفة المجموعة يتم بالتساوي لكل مقعد؛ المطابقة الأكثر دقة اعتمادًا على شكل الطريق الفعلي ما زالت ضمن التطوير.
- ملفات الترحيلات القديمة محفوظة كسجل تاريخي. لا يعني وجودها أن وظائفها القديمة ما زالت مفعلة.
